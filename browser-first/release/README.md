# ResonantOS Workbench — Stable Channel

This directory holds the **frozen SDK workbench**: the version of the
ResonantOS browser extension that SDK building/testing runs against. It
changes only through an explicit release, never while someone is painting
the UI.

## Two channels, one bridge

| Channel | Directory | Profile | CDP | Purpose |
|---|---|---|---|---|
| **dev** | `browser-first/resonantos-side-panel-extension` | `~/.resonantos-test/cft-dev-profile` | 9224 | Live UI work — repainting, new look, ahead of stable |
| **stable** | `browser-first/release/resonantos-side-panel-extension` | `~/.resonantos-test/cft-profile` | 9225 | Frozen SDK workbench — build/test the SDK against this |

Both run against the **same local bridge** (`npm run browser-first:bridge`)
and share the same extension identity, so addon state and delegation flow
through one backend. The UI surface is what differs.

## Commands

```sh
npm run browser-first:bridge   # terminal 1 — shared bridge
npm run cft:stable             # terminal 2 — frozen SDK workbench
npm run cft:extension          # terminal 3 — dev UI workbench (can run alongside)
npm run cft:stable -- --fresh  # wipe the stable profile
node scripts/cft-extension-icon.mjs pin|unpin|status --stable  # toolbar icon on stable
```

Direct equivalents (work without the npm script entries):
`node scripts/launch-cft-extension.mjs --stable` and
`node scripts/launch-cft-extension.mjs`.

## Release flow (dev → stable)

```sh
node scripts/release-extension.mjs   # copy dev over stable + stamp release-info.json
git diff browser-first/release       # review
git commit -am "release(workbench): <version>"  # version control the snapshot
```

Until that commit exists, the stable channel is **not** version controlled.
`release-info.json` records the source commit, timestamp, and version of
each release. Roll back by checking out an older snapshot from git.

## Constraints

- Never hand-edit files under `browser-first/release/resonantos-side-panel-extension` —
  it is generated by `scripts/release-extension.mjs` from the dev channel.
- UI repaints on the dev channel cannot leak into SDK testing: the stable
  profile loads only this directory, and this directory moves only via a release.
- The extension `key` in the manifest must stay identical across channels
  (same extension ID keeps addon state, grants, and toolbar pin intact).

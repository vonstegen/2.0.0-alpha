Findings severity-ranked · cross-vendor + code-verified

F1

Live-browser safety certification isn’t wired

criticalissue filed · #267

All 118 *.test.mjs are deterministic Node mocks. A real CDP harness does exist — agent-control-live.mjs (57 assertions over a password/submit/wallet fixture) — but a follow-up review of the harness itself found its Chrome launcher is orphaned (run-browser-first.mjs became a bridge-only shim in 74199ab, so it hangs on the debug port) and it’s excluded from CI by the *.test.mjs glob. So the #211 boundaries still have zero production evidence — but the fix is smaller than “build a harness.”

Filed as #267 (P0, sub-issue of #211): restore an Alpha-legal launch (playwright@^1.59.1 is already a root dep — launch-only + --load-extension, keep the raw-CDP assertions), CI-gate it, emit proof artifacts.
F2

Public-submit is bypassable via “Approve once”

criticalcode-verified

An in-panel approval sets userApproved:true, which makes the extension programmatically click the Submit button — the agent acts, not the human. This is exactly the behavior #240 exists to eliminate, so #240 must be scoped as a code change (a true human-on-page handoff), not merely “capture a proof” of today’s behavior.

agent-control-runner.js:611 / :847 set userApproved:true → content.js:456 isSubmitLikeElement && !userApproved skips the guard → click proceeds.
Hard boundaries (wallet/payment/credential, content.js:447) are correctly non-bypassable.
F3

beta.1 is epic-heavy and leaf-thin; epics link stale/deferred work

high3/3 vendors

Six open epics (#210–#215) with a thin set of real leaves. Epic bodies still point at old or deferred numbers (#215’s children are mostly scope:deferred; #210/#212/#214 link #113/#103/#97/#178) while the actual work is #218–#241 / #252. As drawn, #215 cannot complete under its own scope math.

F4

Connectors have no OAuth / vault scaffold

high3/3 vendors

beta.2 promises Gmail/Calendar connectors, but there is no chrome.identity / launchWebAuthFlow and no encrypted token vault in the extension. Today’s addon-draft-connectors.mjs is a URL-compose shim. These are “architecture not started,” not “deferred and ready.”

Prerequisite chain: ADR-022 vault (#111) + OAuth token custody + consent/kill-switch (#246) — before #234 / #247 / #248 become real.
F5

Documentation drift vs. actual state

high2/3 vendors

docs/STATUS.md:17 still lists the #209 release gate as “Open” although #209 is closed; CAPABILITY_MATRIX.md marks Agent-Control “certification open” and Provider-Fabric “acceptance open” despite #233 closed. Status races ahead in the feature matrix and lags behind in STATUS — both erode trust for a public audience.

F6

Bridge reliability & stop-signal propagation

medium1/3 vendors

The bridge is a single loopback process with no supervision or crash-recovery, and the MV3 service worker is ephemeral. Stop/cancel is in-memory only and does not propagate an AbortController to an in-flight provider request — a Stop mid-stream leaves the bridge still working. Fold this into #226.

Credit where due — the three-layer safety model (content-script DOM enforcement → extension-runner preflight/approval → host-side plan sanitization) is correctly layered, and Provider Fabric routing / fallback / bridge-auth are well-tested deterministically. The problem is verification method, not architecture.

How a contribution flows issue → PR → green CI

01

Claim an issue

Comment to claim it. Every issue carries a Contributor handoff block — an entry-point file, a focused test, and the runtime boundary.

02

Start from the file

Open the named module. Read AGENTS.md + docs/reference/CAPABILITY_MATRIX.md for context. Stay inside the browser-first Alpha runtime.

03

Test as you go

Run node --test <file> to target one suite. npm run test:browser-first runs all 704 — it ignores path args, so use node --test to focus.

04

Open a PR

CI runs verify:alpha (build + docs + the full suite). Green CI + a short “what/why” is all a review needs.

What the Augmentor must never do the human-only boundaries

If you touch Agent Control, these lines are load-bearing. The extension refuses them by design — a change that lets any of these happen automatically is a regression, not a feature.

BoundaryRuleReference
Public submit / post / publishPrepared, then the human clicks it on the page — never auto-submitted#240 · #268
Password / payment / card fieldsNever typed into by the agent; human-only#224
Wallet connect / sign · checkout · loginHard-blocked; refused, not approvable#12 · #211
Email / calendar sendDraft only; the human sends#234 · #235
Stop / cancelAlways available; leaves no dangling action#226
If you’re testing and the agent crosses one of these without an explicit human action, stop and file a security issue — that’s a boundary regression.

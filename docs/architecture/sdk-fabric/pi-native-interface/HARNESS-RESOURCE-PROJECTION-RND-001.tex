\section{Principle}
A harness consumes a governed session projection of ROS resources. Classification is descriptive, resource declarations are requests, and the host remains authority.
\section{Initial resources}
Provider Profiles/models, project/cwd, project-scoped files, read-oriented Memory, selected bounded ROS tools, and where currently supportable selected Skills. User Profile, DAR, Map, and the universal resource bus remain future seams.
\section{Pi reference}
External Terminal and Embedded PTY receive the same logical resource projection. Pi retains native tool semantics while ROS supplies governed sovereign resources.
\section{Security}
No raw credentials, no blanket user state, no self-grant, per-session/project scope, read-oriented memory, tool-specific capability enforcement, cross-harness isolation, revocation fencing, and fail-closed unknown resources.

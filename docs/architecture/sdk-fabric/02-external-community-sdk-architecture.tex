\section{Objective}
The External SDK is the stable community-facing boundary. A human or AI developer classifies the intended add-on, obtains category-specific contracts/templates/security guidance/tests, builds, validates, installs, grants, enables, operates, and revokes it.
\section{Canonical categories}
Harness, Tool, Connector, Communication, Data Source, UI, and Service.
\section{Community SDK 0.1 basis}
Pi proves the harness path; Utility proves the bounded tool path; Reference Memory provides a data-source basis; GitHub is the recommended next connector reference.
\section{Stable boundary}
The public boundary comprises the manifest/classification contract, validator/category discovery, capability/grant lifecycle, approved runtime/service contracts, declarative surfaces, Provider Profile integration, slot eligibility, public errors, examples, and tests.

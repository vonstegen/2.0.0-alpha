# ResonantOS 2.0.0-alpha — Architecture Baseline

**Baseline candidate:** `c594ca3cec92e02fa35c39016e1dc618939ec7d6`  
**Status:** Alpha candidate; not merged when this pack was created.

## Baseline
The current alpha already contains core primitives for a modular ResonantOS: minimal-kernel philosophy, capability-gated add-ons, system slots, provider routing, a memory-provider broker, governed harnesses, central Provider Profiles, mandatory canonical classification, machine-readable category discovery, and dynamic tool-panel surfaces.

- ADR-026 defines the minimal kernel and replaceable defaults.
- `packages/addon-sdk` is the author-facing SDK boundary; host privilege enforcement remains outside it.
- Candidate `c594ca3` removes the obsolete top-level `category` and makes `classification` mandatory.
- Existing system slots include `primary-agent`, `chat-interface`, `memory-system`, and `communication-channel`.

## Current architecture
- **Kernel/shell:** registry, grants, lifecycle, IPC/host mediation, recovery and system-slot ownership.
- **Provider Fabric:** central provider/runtime routing and Provider Profiles.
- **Harnesses:** `agentRuntime`, harness registry, primary-agent swapping and shared Provider Profiles.
- **Memory:** `memory-system` slot plus neutral broker/reference provider.
- **Dynamic SDK:** seven canonical categories and `describe-category` machine discovery.
- **Dynamic UI:** declarative `tool-panel`/`workspace` surfaces rendered from host-authorized projections.

## Canonical add-on dimensions
- `classification` — WHAT the add-on is.
- `runtimeType` — HOW it executes.
- `surfaces` — WHERE it appears.
- `requestedCapabilities` — WHAT authority it requests.
- `systemSlots` — WHAT ROS role it may occupy.
- `credentialSource` / `providerRequirements` — HOW authentication/provider resources are obtained.

Classification is descriptive only and never grants authority.

## Current gaps
- No universal `provides` / `requires` port fabric yet.
- Not every ROS subsystem is behind a uniform system-module contract.
- Durable encrypted credential storage remains future work.
- Provider-native AI application connectors and sovereign context projection remain R&D.
- Kernel modularity is an internal development architecture, not ordinary add-on replaceability.
